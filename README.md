# SMS Spam Classification — ЛР1 / ЛР2

Направление: NLP. Задача — определить, является ли текст SMS спамом (`spam`) или обычным сообщением (`ham`). Потенциальный пользователь — оператор сервиса фильтрации сообщений; вход — одна строка, выход — класс. API пока не реализован.

## Воспроизведение

Команды выполняются из корня проекта на Linux. Использован Python 3.14.4; версии библиотек закреплены в `requirements.txt`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
curl --fail --location https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip -o data/sms_spam.zip
python -m src.prepare_data data/sms_spam.zip
python -m src.train
python -m src.evaluate_model
python -m src.robustness
python -m pytest tests/ -q
python -m src.verify_model
python -m src.demo_predict
python -m bandit -r src/
```

Данные и модель не распространяются через текущую версию Git: датасет загружается из официального источника и проверяется относительно эталона ЛР1 в `data/dataset.sha256`; модель воспроизводится командой обучения. Скрипт распаковывает только нужный файл, проверяя размер архива, декодированных данных и SHA256; никакие скрипты из датасета не запускаются.

## Одна модель и одно разделение

Единственный действующий артефакт — `models/spam_pipeline.joblib`: TF-IDF (1–2-граммы, `min_df=2`, `max_features=30000`) + LogisticRegression (`class_weight=balanced`, `max_iter=1000`, seed 42). Хэш — `model.sha256`. Предобработка включена в Pipeline и обучается только на train. Название файла, хэш и отпечатки разделения сохраняются в `metrics/baseline.json`.

Нормализованные дубли (регистр и пробелы) удаляются до стратифицированного разделения 80/20. Из 5572 SMS остаётся 5157: train 4125, test 1032. Нормализованных пересечений train/test нет. TF-IDF с линейной моделью — простой и быстрый ориентир для разреженного текста на CPU. DummyClassifier показывает результат всегда наиболее частого класса.

`src/train_model.py`, `src/check_robustness.py`, `src/test_2_robustness.py` оставлены только как команды совместимости: они вызывают основную процедуру. Второй модели и независимых алгоритмов разделения в них нет.

Актуальные результаты: `metrics/baseline.json`, `metrics/evaluation.json`, `metrics/robustness.json`, `metrics/pytest_results.txt`, `metrics/pytest_results.xml`, `metrics/bandit_report.json`. Краткий разбор — [docs/lab2-results.md](docs/lab2-results.md).

Ноутбуки `notebooks/spam_analysis.ipynb` и `notebooks/baseline_sms.ipynb` содержат проверку данных, обучение, метрики и визуализации без публикации исходных SMS. Не добавляйте в Git локальные CSV с текстами. Ошибки классификации и парные изменённые SMS сохраняются только в игнорируемых `metrics/*private*.csv` для локального анализа.

## Ограничения данных

[SMS Spam Collection, UCI](https://archive.ics.uci.edu/dataset/228/sms+spam+collection): исходный файл 477907 байт, 5572 текстовых сообщения, два класса; исходно 4825 ham и 747 spam. После удаления нормализованных дублей: 4515 ham и 642 spam. Это достаточно для учебного baseline с обоими классами в train/test, но не доказательство достаточности для эксплуатации: тексты англоязычные, исторические, нет гарантированных групповых идентификаторов кампаний и современных/русскоязычных сообщений. Близкие шаблоны могут оставаться. Дисбаланс требует F1, Precision и Recall для spam, а не одной Accuracy. Гиперпараметры по test не настраиваются.

## Валидация и настоящие тесты

Единый интерфейс — `src.predict_sms.predict_sms(message, model)`. Принимается непустая UTF-8-совместимая строка без NUL, максимум 1000 символов; None, NaN, Inf, неверные типы и превышение лимита отклоняются с `InputValidationError`. 1000 символов покрывает составные SMS, сохраняя небольшой предел на обработку текста; это инженерный предел, не критерий принадлежности распределению. Ограничение действует после получения строки; будущему HTTP API потребуется отдельный предел запроса до декодирования. Файлового интерфейса предсказания пока нет.

Все тесты используют настоящий обученный Pipeline. Для проверки отсутствия вызова модели на неверном входе наблюдается реальный стек вызовов через `sys.setprofile`; методы модели не заменяются. Проверяются также положительный вход, граница 1000/1001, искусственный предел 20/21, целостность и загрузка модели, совпадение baseline и принадлежность экспериментальной выборки test. Mock и подставных моделей нет.

## Безопасность

Загружайте только собственный проверенный joblib: этот формат способен исполнять код. Проверка SHA256 перед загрузкой обнаруживает изменение относительно эталона, но не превращает чужой артефакт в доверенный. `.env` содержит пароли/токены, поэтому исключён из Git: публикация дала бы доступ к соответствующим сервисам. `.gitignore` не удаляет ранее созданные коммиты.

Обоснование исторического B311 и границы проверки Jupyter: [docs/security.md](docs/security.md). Требования ЛР1 и мини-модель угроз: [docs/lab1-status.md](docs/lab1-status.md). Jupyter и системные настройки этим изменением не перенастраивались.

Преподаватель может воспроизвести модель по командам выше. Для передачи готового артефакта используйте приватный канал: `models/spam_pipeline.joblib` вместе с `model.sha256`; публичной ссылки на бинарную модель нет.
