# SMS Spam Classification — ЛР1 / ЛР2 / ЛР3

Направление: NLP. Задача — определить, является ли текст SMS спамом (`spam`) или обычным сообщением (`ham`). Потенциальный пользователь — оператор сервиса фильтрации сообщений; вход — одна строка, выход — класс. API пока не реализован.

## ЛР3 Безопасный CI/CD

GitHub Actions запускает [ci.yml](.github/workflows/ci.yml) при push и pull request. Порядок обязательных проверок: получение данных с SHA256 и восстановление модели → Ruff → Bandit → настоящие тесты → pip-audit → data gate → оценка кандидата → model gate → сборка Docker → проверка Dockerfile → сканирование образа и security gate → non-root и smoke. Ошибка останавливает последующие этапы. Отчёты сохраняются также при отказе через `if: always()`; статус отказа не скрывается.

Рабочее окружение ЛР2 и настройки Jupyter не изменяются. Для проверок используется отдельное окружение:

```bash
cd ~/ml-project
python3 -m venv .lab3-venv
source .lab3-venv/bin/activate
python -m pip install --only-binary=:all: -r requirements-ci.txt
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
source ci/env.sh
python -m ci.prepare
# На сервере, где Docker требует sudo:
sudo -v
LAB3_DOCKER_SUDO=1 bash ci/run_local.sh
# На GitHub-hosted runner / при доступном Docker без sudo:
# bash ci/run_local.sh
```

`requirements-runtime.txt` фиксирует полный набор из 11 runtime-зависимостей, `requirements-ci.txt` — версии инструментов проверки. Обучение не зависит от ноутбука. CI-профиль размещает кандидатную модель, её манифест и сведения запуска отдельно в `ci-artifacts/`. На сервере кандидат копируется из проверенного артефакта ЛР2; на чистом runner обучается с теми же параметрами и seed на проверенных данных. Побайтовое совпадение сериализации между разными машинами не предполагается: SHA256 кандидата записывается в его отдельный манифест и проверяется перед загрузкой и внутри Docker. Тесты сравнивают качество с закреплёнными результатами ЛР2. `ci.prepare` не меняет `metrics/baseline.json`, `config/model_baseline.json`, исходную модель и `model.sha256`.

Контроль CI — 20 фиксированных сообщений из отложенной выборки ЛР2, 10 ham и 10 spam, без пересечения с train. В Git сохраняются ID, схема, версия и SHA256; тексты формируются локально в игнорируемом `ci-artifacts/control.json`. Источник, политика пропусков, ограничения и границы классов: [data_policy.json](config/data_policy.json). Пропуски и неверные SMS отклоняются, заполнение не применяется. Повторяемый контроль CI не заменяет независимую итоговую оценку на полном test.

Model gate использует F1 класса spam (`pos_label='spam'`, `zero_division=0`) на одной и той же контрольной выборке. [Baseline](config/model_baseline.json) — 0,9473684211; порог `baseline × 0.95` — 0,9000. F1=0,9160305344 относится к полному test из 1032 SMS и не смешивается с метрикой контрольной двадцатки. Baseline и [политика](config/model_policy.json) хранятся отдельно от метрик кандидата; отсутствующие, нечисловые, NaN/Inf и несовместимые по версии/хэшу результаты отклоняются.

Политика безопасности: любая известная уязвимость из `pip-audit` блокирует pipeline. Для образа блокируются CRITICAL и UNKNOWN; неизвестная серьёзность не считается безопасной. Dockerfile проверяется отдельно на HIGH, CRITICAL и UNKNOWN. Ошибки загрузки базы и выполнения сканера также завершают этап с ошибкой. Полных исключений и `continue-on-error` нет. Trivy устанавливается из официального GitHub Release v0.76.1 с проверкой закреплённого SHA256 архива. Дата проверки, версии и сведения о commit сохраняются в отчётах, потому что базы уязвимостей меняются.

Dockerfile использует официальный `python:3.14.4-slim-trixie` с digest, только runtime-зависимости и явный список файлов. Данные, `.git`, окружения и секреты исключены из контекста через allowlist в `.dockerignore`. В образ включён только проверенный локальный `spam_pipeline.joblib` и его манифест. Пользователь контейнера — UID/GID 10001. Smoke запускается с read-only filesystem, отключённой сетью, сброшенными capabilities и `no-new-privileges`. Docker socket в контейнер приложения не передаётся. Публикация образа в registry и развёртывание сервиса не включены в обязательную часть ЛР3.

Для CI не нужны пользовательские секреты. Права workflow — `contents: read`; checkout не сохраняет credentials. Действия закреплены полными commit SHA, Python и scanner — версиями, job ограничен 25 минутами. Код внешнего PR не получает пользовательских токенов. В публичные artifacts загружаются только диагностические отчёты: исходные SMS, модель, копия датасета и архив образа исключены явным списком путей.

Три отдельные демонстрации управляются `config/ci_scenario.json` и выполняются в ветках `lab3/demo-*`: `data` меняет метку только в одноразовой копии контрольных данных; `model` оценивает настоящий сохранённый константный классификатор; `security` подаёт явно обозначенный безопасный имитированный отчёт с CRITICAL в проверку политики. Последний сценарий проверяет логику security gate и не выдаётся за реальное сканирование. Реальные pip-audit и Trivy выполняются отдельно в успешном pipeline. Итоговая main использует `success`. Подробности и ссылки на запуски: [docs/lab3-results.md](docs/lab3-results.md).

## Воспроизведение

Команды выполняются из корня проекта на Linux. Использован Python 3.14.4; версии библиотек закреплены в `requirements.txt`.

```bash
python3 -m venv .venv
source .venv/bin/activate
unset ML_MODEL_PATH ML_MODEL_MANIFEST ML_EXPERIMENT_METADATA ML_ROBUSTNESS_REPORT
python -m pip install -r requirements.txt
curl --fail --location https://archive.ics.uci.edu/static/public/228/sms+spam+collection.zip -o data/sms_spam.zip
python -m src.prepare_data data/sms_spam.zip
python -m src.train
python -m src.evaluate_model
python -m src.robustness
python -m pytest tests/ -q
python -m src.verify_model
python -m src.demo_predict
python -m bandit -r src/
```

Данные и модель не распространяются через текущую версию Git: датасет загружается из официального источника и проверяется относительно эталона ЛР1 в `data/dataset.sha256`; модель воспроизводится командой обучения. Скрипт распаковывает только нужный файл, проверяя размер архива, декодированных данных и SHA256; никакие скрипты из датасета не запускаются.

## Одна модель и одно разделение

Единственный действующий артефакт — `models/spam_pipeline.joblib`: TF-IDF (1–2-граммы, `min_df=2`, `max_features=30000`) + LogisticRegression (`class_weight=balanced`, `max_iter=1000`, seed 42). Хэш — `model.sha256`. Предобработка включена в Pipeline и обучается только на train. Название файла, хэш и отпечатки разделения сохраняются в `metrics/baseline.json`.

Нормализованные дубли (регистр и пробелы) удаляются до стратифицированного разделения 80/20. Из 5572 SMS остаётся 5157: train 4125, test 1032. Нормализованных пересечений train/test нет. TF-IDF с линейной моделью — простой и быстрый ориентир для разреженного текста на CPU. DummyClassifier показывает результат всегда наиболее частого класса.

`src/train_model.py`, `src/check_robustness.py`, `src/test_2_robustness.py` оставлены только как команды совместимости: они вызывают основную процедуру. Второй модели и независимых алгоритмов разделения в них нет.

## Ограничения данных

[SMS Spam Collection, UCI](https://archive.ics.uci.edu/dataset/228/sms+spam+collection): исходный файл 477907 байт, 5572 текстовых сообщения, два класса; исходно 4825 ham и 747 spam. После удаления нормализованных дублей: 4515 ham и 642 spam. Это достаточно для учебного baseline с обоими классами в train/test, но не доказательство достаточности для эксплуатации: тексты англоязычные, исторические, нет гарантированных групповых идентификаторов кампаний и современных/русскоязычных сообщений. Близкие шаблоны могут оставаться. Дисбаланс требует F1, Precision и Recall для spam, а не одной Accuracy. Гиперпараметры по test не настраиваются.

## Валидация и настоящие тесты

Единый интерфейс — `src.predict_sms.predict_sms(message, model)`. Принимается непустая UTF-8-совместимая строка без NUL, максимум 1000 символов; None, NaN, Inf, неверные типы и превышение лимита отклоняются с `InputValidationError`. 1000 символов покрывает составные SMS, сохраняя небольшой предел на обработку текста; это инженерный предел, не критерий принадлежности распределению. Ограничение действует после получения строки; будущему HTTP API потребуется отдельный предел запроса до декодирования. Файлового интерфейса предсказания пока нет.

Все тесты используют настоящий обученный Pipeline. Для проверки отсутствия вызова модели на неверном входе наблюдается реальный стек вызовов через `sys.setprofile`; методы модели не заменяются. Проверяются также положительный вход, граница 1000/1001, искусственный предел 20/21, целостность и загрузка модели, совпадение baseline и принадлежность экспериментальной выборки test. Mock и подставных моделей нет.

## Безопасность

Загружайте только собственный проверенный joblib: этот формат способен исполнять код. Проверка SHA256 перед загрузкой обнаруживает изменение относительно эталона, но не превращает чужой артефакт в доверенный. `.env` содержит пароли/токены, поэтому исключён из Git: публикация дала бы доступ к соответствующим сервисам. `.gitignore` не удаляет ранее созданные коммиты.

Обоснование исторического B311 и границы проверки Jupyter: [docs/security.md](docs/security.md). Требования ЛР1 и мини-модель угроз: [docs/lab1-status.md](docs/lab1-status.md). Jupyter и системные настройки этим изменением не перенастраивались.

Преподаватель может воспроизвести модель по командам выше. Для передачи готового артефакта используйте приватный канал: `models/spam_pipeline.joblib` вместе с `model.sha256`; публичной ссылки на бинарную модель нет.
