# Подтверждённые результаты ЛР4

Дата проверки: 05.11.2026. Реализованы обязательные пункты 1–8 и 10 задания.
Prometheus/Grafana — дополнительный пункт 9; отдельные серверы не развёрнуты.
Используются работающие Prometheus-метрики, JSON-логи и проверенное правило обнаружения.

## Реализация

FastAPI `/predict`, `/health`, `/metrics`, `/monitoring/detection`, веб-страница
из `static/`. Исходная модель ЛР2: TF-IDF + LogisticRegression, версия `sms-lab2-v1`.
SHA256 проверяется относительно отдельного манифеста до загрузки; один процесс модели
загружается на старте и переиспользуется. При ошибке загрузки health=503.

Защита: серверная строгая схема, потоковый предел 8192 байт, до 1000 символов,
bearer-аутентификация, отдельный токен мониторинга, limiter 20 / 60 секунд по IP,
deadline чтения 2 секунды, одно предсказание без очереди и hard timeout 2 секунды
с завершением/ожиданием процесса и последующим восстановлением.

Контейнер работает с UID/GID 10001, read-only, без capabilities и новых привилегий,
с ограничениями PID/CPU/памяти. На хост опубликован только `127.0.0.1:8000`.
Секреты — runtime env-файл вне Git с правами 600. Доступ пользователя — SSH-туннель.

## Сценарий обнаружения

`python -m ci.lab4_demo` запускает отдельный временный сервис. Предел: 4 запроса
за 2 секунды; правило: минимум 3 ответа 401/429 на `/predict` за 3 секунды.
Фактический временной интервал каждого прогона записывается в `ci-artifacts/lab4/demo.json`.

Наблюдалось: 200 → 401, 401, 401, 429 → active=true → ожидание 3.2 секунды →
200 и active=false. Получены настоящие сетевые ответы, JSON-логи и Prometheus-снимки
до, после и после восстановления. Ввод и токены в логи/labels не включены.
Негативные запросы не вызывают модель; это дополнительно подтверждают API-тесты.
Сигналы HTTP показывают поведение сервиса, а не доказывают атаку на модель или потерю точности.

## Материалы и воспроизведение

Команды и ограничения: [README_LAB4.md](../README_LAB4.md).
CI: [GitHub Actions](https://github.com/MrPodushkin/ml-project/actions/workflows/ci.yml).
В артефактах `lab4-reports-<run_id>` находятся pytest, сканеры, gates, HTTP-smoke,
логи и снимки метрик. Модель, датасет и runtime-токены не публикуются.

На сервере используется проверенная копия исходного артефакта ЛР2
`f054edc2c35248ad9cb26a78ce7d8be044558fe39d3d73d8cf487777bbfeb06a`.
На чистом GitHub runner CI воспроизводит кандидат с теми же параметрами на проверенных
данных, проверяет его собственный манифест и сравнивает метрики с закреплённым baseline.
Побайтовое совпадение сериализации разных окружений не требуется.
